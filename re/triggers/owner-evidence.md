# Owner activation: reviewed refinements and limits

This is RE-side evidence. No code or assembly is reproduced here. The owner
tables use the ledger's owner attribution, not a claim that every attributed
entry is an exclusive method of that class. In particular, `nSGLDX7::cGDriver`
also has some other-backend bodies attributed to it (renderer-driver.md section
1), and `cGZWWWSystem` includes neighbouring FTP bodies (web-network.md section
4). Their proposed scenarios cannot promise all of those bytes.

## Construction checked separately from activation

The software span objects are allocated inline by
`cGZDrawContextRenderToBuffer::Init` at `00830710`; there is no separate named
constructor required. Instructions checked with bytes at `0083077c–008307ee`
allocate and install the specific tables: 1555 at `0083078a`, 565 at `008307a0`,
4444 at `008307b6`, 8888 at `008307cc`, and 8-bit at `008307e2`. The common
creator retains the result in its context. The corresponding creation rules are
in span-render-1555.md section 1.1, span-render-4444.md section 1 and
span-render-8.md section 10. The preceding instructions query the target buffer
format and select a case (`0083075d–00830775`). Consequently a software 3D launch,
a city redraw or a snapshot is insufficient evidence that every target format
exists. No verified player/script consumer supplying all formats is established.

The city-detail object also has inline creation: factory `0045d420` allocates
the object and installs its tables at `0045d42e–0045d43b`, then initializes its
state. The native bytes were checked through `0045d453`. The factory's COM
registration and per-city component ownership are city-detail.md section 1.

Three unnamed constructors are identified by their existing behavioral specs
and checked against direct export callers: growth developer `006b7310`, called
at `00699207` and by factory `006b7870` at `006b7883` (growth-developer.md section
1); occupant manager `004a0540`, called by factory `004a18a0` at `004a18b3`
(occupant-manager.md sections 1–2); water pathfinder `007250f0`, created from
traffic initialization at `0071f745` (traffic-network.md section 1). The last is
an internal traffic object, not a separately registered COM class.

For the other entries, `owner-creation.tsv` preserves exactly which evidence was
found. A named constructor and its export caller are stronger than an unnamed
function which writes a class table. The 41 latter candidates are not promoted
to confirmed constructors. Thirty-three owners still have only lifecycle or
consumer witnesses; three rows are namespace/free-function groups for which a
class constructor does not apply. Missing construction evidence remains a task
gap, not a dead-code finding.

## UI and play conditions

The query constructor `004c4590` has two direct creators in the 3D window command
handler (`007f2752`, `007f27b4`). Selecting a query tool therefore has a concrete
owner-creation route, but separate map input is needed to query an occupant.
The network constructor `0062c5f0` has manager creators in `GetNetworkTool`
(`0061090b` onward) and `Init`; the power-line specialization is created at
`006109e4`/`00610e7d`. Dated private-tool placement can activate these owners
without exercising interactive dragging or every network validation branch.

The sub-budget constructor `007862b0` is called by the budget panel detail path
at `0076848e` and by the individual-budget path at `0078655b`. Budget-window.md
section 2.1 maps compact-panel button `AA3AC403` to the civic department group;
its decimal form 2855977987 is the candidate's public UI control ID. The panel
must already exist, and global lookup and modal closing remain uncalibrated.
This is a UI ID, not an executable address or a substitute for slider input.
The encoded button-message check and compact button dispatch were checked in
the instructions at `0076897b–007689a9` and `00768c9d–00768cac`; the individual
department selector mapping is the existing budget-window section 2.1 rule.

My Sim construction is not resident activation: mysims.md section 1.2 places
the advisors under the advisor system and the agent under the city. A resident
must actually be added, dispatched and observed; compatible character import is
a separate prerequisite. City-situation.md section 0 makes the analogous
distinction for U-Drive-It: without a started mission its animation callback is
idle. The debug-only `csitrigger` route is not assumed available in normal play.

Text-effect parser objects are authoring consumers, not the visual effect
instances produced by running compiled binary resources. No ordinary retail
authoring entry has been verified. Likewise an external browser launch is not
proof that the in-game WWW/cache/cookie clients were used. Those candidate
drivers stop explicitly and grant no activation credit.

## Reach and empirical limits

totals retain the pinned provisional pilot; no upstream summary supplies the
address records needed to add scenario reach to this census. The files record
upstream aggregate counts and findings with provenance instead. No new game
scenario, precision, recall, shadow exactness or replacement result is claimed.

artifacts. They are not acceptance evidence for the owner-activation map.
