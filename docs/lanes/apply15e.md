## Questions

1. **`PopState` on a `final` state: push, or replace?** §12 quirk 11 says it "does not reveal the state below — it does `PushState(1, 0, -1.0, 0, 0, 0, 0)` (DISAPPEAR) **instead**". I read "instead" as the pop being *replaced* by the push, so the `final` state stays underneath and the stack does not drain. The other reading is pop-then-push (the `final` state is discarded and DISAPPEAR takes its place). Both keep the state below hidden and both end as DISAPPEAR → `Remove(0)`; they differ in what remains on the stack. **Probe:** disassemble `PopState` (Windows `0x0050B660`, Mac `0x000bd2de`) and see whether it decrements the stack before the push.
2. **Plummet `+0x28` at enter: the two reports never actually disagreed.** §6.5 gives the vehicle report's constant as `0xBB88888A = −0.0080729163` and says the two "differ by roughly 2×". `0xBB88888A` decodes to **−0.0041666673**, which is the automata report's −0.004166667 (−1/240) to the seven digits it was written in; −0.0080729163 is about twice that, which is where the "roughly 2×" comes from. I implemented −1/240 / `0xBB88888A` and pinned both facts in a test. **Ask:** confirm the hex in `HandleEnterState` case `0x0E` and re-state the constant; if the decimal is right and the hex is not, say so and I will flip it.
3. **PullOver `+0x28`: the latch reading.** §6.5 gives two readings; I implemented the elapsed-milliseconds counter, because the tick ends with `+0x28 += dt` and the finish branch runs at `+0x28 ≥ 1000`, neither of which the "already initialised" latch reading carries. The latch reading (`if (+0x28 == 0.0)` seeds `+0x2C..+0x34` from the orientation and `+0x38..+0x40` as its −90° Y-rotation, Win `0x0055E550` / Mac `0x000a2978`) is filed here. **Probe:** watch `+0x28` across a pull-over.
4. **`+0x0C` on read versus corpus round-trip.** §12 quirk 10 says "It round-trips, but a replacement must recompute it after any stack mutation rather than trust the stream", while §14 test 29 says "A record read from a stream must have `+0x0C` recomputed rather than trusted". The corpus holds **14** states whose stored `+0x0C` is stale — a state alone on its stack still carrying the index it had when a second state sat below it — so the two sentences cannot both hold for those 14. I implemented recomputation on read *and* after mutations, and the save sweep reports exactly those 14 as index-renormalised (count pinned) while every other byte matches. If byte-identical re-encode is preferred for the whole corpus, drop the recompute-on-read half and the field keeps its stale values.
5. **Write's version upgrade for the state base.** §6.2 says "Write **always emits version 3 and all seven fields**, whatever version was read", and QUESTIONS.md AM1 agrees. The engine deliberately writes each record with the version it was read with (a documented `[choice]` in `automata/mod.rs`) so the corpus re-encodes byte-identically. This is not in the DIFFERS list, so I left it alone. **Ask:** which behaviour is wanted for the state base?
6. **`0x2A7B582E`'s match (effects.md §16 EF6).** EF6 leaves open whether the location update matches on `data1 == instance` or on something else. I implemented `data1 == the instance` — the §12 message-table contract, and what the sibling `0xCA493C1D` already does — and adjusted `ds00_short_form.json` accordingly. If the original matches on something else, this is the place to change.

## Scope notes (not questions)

- The visual-effects **manager** is not implemented in the engine: `engine/core/src/effects/` is new and holds only the rules the DIFFERS cover (LOD predicate, runtime flags, the finish rule, the `volcano_control` finish condition and the `data1` provenance). The tick, the brush and game records, the select-group draw and the draw pass are not modelled. `engine/formats::effects` parses the directory.
- The state's `+0x20` automata-flags **enter/exit rules** (on enter `state+0x20 = automaton+0x84`; on exit `automaton+0x84 = (automaton+0x84 & 0x600C001) | state+0x20`) are not modelled: this core has no enter/exit handlers and movement and animation are stubbed. The field round-trips.
- The two conformance vectors of §14 that need live ticks (test 28 "returned 0 means the generic seek", test 30 "`dt` is ms, tween durations are seconds") are not written: this core has no `DoStateTick` at all.
