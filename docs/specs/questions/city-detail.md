- **CD6 - §3.1/§3.3, in-game increase pass:** the increase pass needs the current setting above the stored level. The harness slot's preference is 1 and Konradshohe's record is 3, so a game run can only exercise reduce. The spec gives no public way to raise the setting for a run: (a) is the preference (`SC4Preferences::videoPreferences.cityDetail`) read only from the game's config at start-up, and is there a supported call (for example `cISC4App::ApplyVideoPreferences`, vtables.tsv `cSC4App::vftable_3` slot 19, argument not documented) that sets it; (b) §3.1 says the lot configuration manager filters its catalogue with d when it builds it: at what point is that built, and is it rebuilt when the preference changes? Writing the struct field from the plugin would leave the catalogue filtered at the old d (an increase pass with nothing to create) and the game may write the changed preference back to the user's config at exit. [not exercised in game; the increase pass is covered only by the conformance vectors; a harness `[ini]`/request key for the start-up detail preference would settle it]
