# Framework strings: open questions

Questions about [rz-strings.md](../rz-strings.md). Filed 2026-10-23 by re-strings5.

- **RZS1 — §7, callback reentrancy:** What is the supported result when a callback removes itself, removes another unknown callback, registers a replacement, or recursively invokes the same detokenizer? The observed service iterates its live ordered set and shares the per-token output between failed callbacks. Do not assume snapshot registration semantics. [Unknown; implement ordinary non-mutating callbacks first.]
- **RZS2 — §§4–5, non-ASCII case conversion:** Determine the exact Windows runtime wide-case tables, owner-level handling of conversion failures and resulting search offsets when UTF-8 byte lengths change. Also determine non-ASCII registry strnicmp collation. [ASCII rules settled; raw conversion and malformed-input rules remain canonical in string-encoding.md and its prior MakeLower witness; no host Unicode folding substitution is specified.]
- **RZS3 — §§1–3, mutation boundaries:** Determine alias-overlap guarantees for setters/append/insert/replace, allocation-failure outcomes and maximal byte counts; distinguish normal range errors from crash/termination and adapter policy. [Ordinary independent-range edits settled; no recoverable false return inferred.]
- **RZS4 — §§2/5, native split helpers:** Settle complete argument order, empty-field consumption, no-match output and repeated-separator rules for SplitTokenDelimited 0x0090F335 and SplitTokenSeparated 0x0090F39D. [SplitToken 0x0090E98C is separately specified; do not alias these methods to it.]
- **RZS5 — §5, Sprintf edges:** Verify signed negative/extreme integers and exact sign/prefix order, negative dynamic width/precision, unsupported/wide conversions, null strings, malformed/trailing percent, embedded-NUL %c and %n destination/value semantics. Verify glyph counting and precision for invalid encodings. [Literal/%%/%s and positive unsigned/padding vectors settled; no complete host printf equivalence claim.]

- **RZS7 — §5.1, reproducible finite decimal intermediate:** Specify the 12-byte extended representation (significand width, exponent and rounding), scaling constants, operation order and rounding points used to generate the 17 digits and guard. Section 5.1 says legacy extended scaling can affect the last digit and expressly excludes exact/arbitrary-precision binary64 conversion as an equivalent, but does not define an algorithm that distinguishes the two. Include boundary witnesses where extended scaling differs from exact binary64-to-17-digit half-up rounding, plus smallest subnormal/largest finite results. [Core implements all post-intermediate rounding/assembly, integer/pointer rules, zero and special markers; finite nonzero decimal extraction remains an explicit LegacyDecimal provider. The 20 RZS6 vectors are covered, using an exact-rational test provider for their finite inputs; this does not claim parity for unvectored legacy intermediates.]

- **RZS8 — §§2/5, nonvirtual helper ABI for same-process shadows:** Please specify exact native prototypes and x86 calling conventions for Mid/Left/Right and MakeLower/MakeUpper, including substring return storage (hidden result pointer, ownership, construction/destruction obligations) and whether the case helpers return the receiver or no value. The spec gives behavior and entry addresses, but the SDK's cRZBaseString explicitly implements its own different class and does not establish these native signatures. [Do not guess signatures: monthly strings_shadow measures published virtual string operations and integer/string Sprintf; these nonvirtual helper paths remain excluded pending a native ABI contract.]

- **RZS9 — §4, CompareTo differing-prefix return magnitude:** The spec specifies ordering signs and original length differences for equal common prefixes. Does an unequal prefix return normalized -1/+1 rather than the byte difference? In same-process native calls, `Konradshohe` versus `Ab` returns +1 (sensitive and insensitive), while production core returns +10; `abABabcdef` versus `AB` sensitive returns native +1/core +32. [No core behavior change inferred from observations. The measured shadow subset now uses equal common prefixes, whose original length difference is explicitly specified; differing-prefix raw magnitudes remain excluded.]

- **RZS10 — §5, alternate hexadecimal prefix with zero padding:** Please settle `%#010x` padding placement. For unsigned 3473 (0xd91), native Sprintf emits `000000xd91`, while core emits `0x00000d91`; this accounts for four differences per month in the initial run's integer/string formatting sample. [Keep this flag combination excluded from the measured shadow; plain `%08x`, signed positive `%+08d`, `%s` and `%%` remain measured. No host-printf substitution or observation-driven core change.]
