- **PR6 - sections 4 and 9, isolated native factory registry:** is there a published GZCOM class ID and complete typed lifecycle for acquiring an independently OWNED original manager, or a scoped public factory-registration route that removes both factory-ID entries and type associations? The SDK publishes only the system-service smart pointer; section 4 explicitly retains type associations after removal, and Shutdown retains them too. Registering a fixture factory on the application manager cannot meet the lane's complete-cleanup requirement. The SDK also declares slot 20 as a factory pointer, whereas the contract takes a class ID. [Exclude native factory registration/removal, factory-driven loading/creation and isolated lifecycle tests; never invoke a private constructor, reinterpret a class ID as a pointer, or shut down the global service. Resource-only cache fixtures use the typed public manager route and fully remove their own keys.]
