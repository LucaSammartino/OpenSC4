- **RZS7 — §5.1, reproducible finite decimal intermediate:** Specify the 12-byte extended representation (significand width, exponent and rounding), scaling constants, operation order and rounding points used to generate the 17 digits and guard. Section 5.1 says legacy extended scaling can affect the last digit and expressly excludes exact/arbitrary-precision binary64 conversion as an equivalent, but does not define an algorithm that distinguishes the two. Include boundary witnesses where extended scaling differs from exact binary64-to-17-digit half-up rounding, plus smallest subnormal/largest finite results. [Core implements all post-intermediate rounding/assembly, integer/pointer rules, zero and special markers; finite nonzero decimal extraction remains an explicit LegacyDecimal provider. The 20 RZS6 vectors are covered, using an exact-rational test provider for their finite inputs; this does not claim parity for unvectored legacy intermediates.]

  **ANSWERED 2026-10-24 (re-rzstrings-rzs7):** DIFFERS — §5.1.1 defines exact widening into an 80-bit significand with bias-16383 exponent, the fifteen-product truncated multiply and its ties-to-even rounding, all reachable base-eight scaling constants and their adjustment, signed decimal-position estimate, ordered scaling and distinct one-tenth correction, fixed-point extraction and decimal half-up guard rounding. RZ41–RZ50 cover the smallest subnormal, largest finite, normal/subnormal boundary, carry and explicit differences from direct exact-to-17-digit half-up conversion: exact `1000000000000000.25` produces intermediate `10000000000000002` at decimal position 16 and `%.2f` yields `1000000000000000.20`. Results are static RE deductions, not native execution measurements. The open RZS7 entry originated in the blocked lane's worktree and was absent from this lane's base open-question file; its complete entry is preserved here. RZS1–RZS5 remain open.

- **RZS6 — §5, Sprintf numeric conversion and unvectored flag combinations:** What exact digit conversion, default precision, rounding, exponent spelling, non-finite spelling and alternate-form rules apply to e/E/f/g/G, and what byte spelling does p produce? Please also pin integer zero with zero precision, alternate octal/hex prefixes and interaction of numeric precision with zero field padding. The syntax inventory alone does not define these outcomes. [Core owns parsing, argument selection, integer digits and field assembly; float/pointer digit conversion is an explicit caller-supplied FormatPrimitives boundary pending this answer, never an assumed whole-format host printf. Unvectored integer precision/prefix combinations use the literal conventional digit interpretation, marked in code; native parity for those combinations remains open.]

  **ANSWERED 2026-10-23 (re-rzstrings-rzs5):** DIFFERS — §5.1 and RZ21–RZ40 specify the bundled runtime's 17-significant-digit intermediate, decimal half-up rounding, default precision 6 (zero `g` precision means 1), precision cap 512, three-digit signed exponents, alternate floating forms and legacy non-finite text. Pointer output is eight uppercase hex digits without a prefix. Integer zero is never suppressed by zero precision; alternate octal/hex prefixes are unconditional, precision excludes prefixes and does not disable zero field padding, which precedes the prefix. Conventional host printf combinations therefore differ. The vectors are static RE deductions, not native execution measurements; RZS1–RZS5 remain separate.
