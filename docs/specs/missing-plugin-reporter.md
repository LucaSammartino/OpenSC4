# Missing-plugin data reporter

## Scope and evidence

This is the first dedicated contract for the original Windows `cSC4MissingPluginDataReporter`, limited to `DoPostCityInit` (`0x0048C6D0`) and `DoMessage` (`0x0048C8F0`). Export sizes 532 and 33 bytes identify the bodies; their sum is not a coverage or execution claim. Foreign occupant-manager, filter, property, allocator and dialog operations remain primitives. Intrinsic shared container and property-adapter instructions are used only to resolve the reporter's own rules. No native execution or replacement implementation supplied the results below.

Source identity, checked 2026-10-23: main-checkout `bin/SimCity4.exe`, PE machine `0x014C`, image base `0x00400000`, FileVersion **1.1.641.0**, SHA-256 **`3bc5c7fe807fe5aa24a3abb06e40f13486670bc1150612c09baf4ecedafe1a4b`**. The SHA-256 equals `ghidra/export/windows/export-summary.txt`; all 532 and 33 instruction bytes in the two exported ranges also equal the mapped PE bytes. Primary evidence is `tools/re_query.py asm --bytes` over that export, following [the RE workspace query workflow](../re-workspace.md#querying-in-parallel-lanes). Local decompilation was navigation only: it misreconstructs stack locals and several shared helper names. Windows names are auto-matched (`auto:B0/medium`, Mac `0x001E3AF8`, and `auto:B1/medium`, Mac `0x001E3C8E`); those names alone establish no branch behavior.

## Owner, interfaces and normal domain

Use `R` for the complete reporter address and `F` for the filter pointer stored at `R+0x10`. The listener interface is `R+8`: `DoMessage` makes the explicit minus-eight adjustment. The PE listener table at `0x00A8ED24` contains QueryInterface adjustment thunk `0x0048C210`, AddRef adjustment thunk `0x007637A0`, Release adjustment thunk `0x007637B0`, and `DoMessage` at slot `+0x0C` (`0x00A8ED30`). Each of those three thunks subtracts eight before forwarding. The intrinsic owner QueryInterface body `0x0048C060–0x0048C09C` recognizes full-word IID `0x452294AA`, publishes `R+8`, invokes the complete object's AddRef slot and returns AL one; other IIDs forward to `cRZUnknown::QueryInterface`. No complete owner layout, construction, subscription or shutdown contract is claimed here.

| State/input | Width and use in these bodies |
|---|---|
| `R+0x10` | Pointer passed unchanged as `cISC4OccupantFilter*` to the manager. If the context global below is nonnull, it is dereferenced for the two stores before the manager-presence gate. |
| global `0x00B43DD8` | Nullable context pointer `C`; read only here. If nonnull, copy raw 32-bit `C+0x0C` to `F+0x0C`, then raw 32-bit `C+0x10` to `F+0x10` (`0x0048C6FA–0x0048C70F`). The second source word is loaded before either store. No field units or context class are assigned by this contract. If null, retain both filter words. |
| global `0x00B43D0C` | Nullable manager pointer `M`, used through `cISC4OccupantManager` slot `+0x98`. Captured after the filter stores; null gives the early false return. |
| global `0x00B207E4` | Cached allocator/service interface `A`, used for 12-byte list-node allocation (`+0x0C`) and freeing (`+0x10`). Its own reference policy is foreign. |
| message argument | Live message interface, selector getter at `+0x10`; no null check or AddRef/Release here. |

Normal returning behavior assumes live receivers, valid writable output/filter objects, a well-formed finite circular list, usable container allocations, and foreign calls that return normally without invalidating traversal or temporary state. The null `M` route permits omitting `A` and the list; it does **not** bypass earlier `C`/`F` stores. No null `F` validity is inferred when `C` is null: it is still passed to the foreign manager. Failed allocation, missing allocator, invalid property-holder/variant pointers and reentrancy are bounds, not invented false returns; see [open questions](questions/missing-plugin-reporter.md).

## Message decision contract

`DoMessage` receives the message-listener subobject pointer, asks the message at its first argument for its selector through vtable byte offset `+0x10`, and compares the full 32-bit result with `0xEA8AE29A` (`0x0048C8F9–0x0048C901`). On equality it calls post-init using the listener address minus eight (`0x0048C903–0x0048C906`). Other selectors do not call post-init. Both returning paths set **AL = 1** and return while removing the one stack argument (`0x0048C90B–0x0048C90E`); post-init's boolean does not propagate to the message result. This body has no once-only latch, registration mutation or message payload read.

## Post-init decision contract (normal returning paths)

The invocation starts with a true byte result and a fresh temporary set of **32-bit unsigned values**. After the occupant traversal it tests that set's count as a full 32-bit value (`0x0048C810`). Empty means skip the popup-permission query and dialog. Nonempty means call `SC4GetPopupModalDialogsEnabled` and test **AL**, not the whole return register (`0x0048C817–0x0048C81E`). A false permission result skips the dialog and retains the initial true result. A true permission result reaches the foreign `cSC4MissingPluginPacksDialog::DoDialog` call with the temporary set (`0x0048C844–0x0048C84B`); its **AL** replaces the invocation's saved byte result (`0x0048C852`). Normal cleanup follows even when this byte is zero. A missing manager pointer at `0x00B43D0C` instead destroys the temporary set and returns **AL = 0** (`0x0048C712–0x0048C73E`). These branches do not establish that every missing-content event displays a dialog or that a dialog decline changes persistent reporter state.

The allocation-null edge explicitly rejoins the dialog call with a null receiver (`0x0048C82A–0x0048C82C`, `0x0048C8DD–0x0048C8DF`). Its successful return is outside the normal nonnull-receiver domain; it is not a proved graceful allocation-failure result.

The export's `cSTEChangeTerrainUI::vftable` label is a shared/misleading identity; the direct foreign `DoDialog` call is the boundary that matters. |

The scalar adapter's intrinsic branch is small and necessary to distinguish lookup failure from an output value. It calls holder slot `+0x24` with the property ID; tests the returned property pointer as full **EAX nonnull** (`0x005FD48E–0x005FD493`); on null returns AL zero without writing `value32`; otherwise calls property slot `+0x14` with no arguments to get a variant view, then variant slot `+0x64` with `&value32` and forwards that call's AL (`0x005FD495–0x005FD4AD`). There is no separate boolean-plus-pointer lookup result, no null-holder guard, and no null-variant guard. Conversion internals and whether failure writes an output sentinel remain foreign. Reporter behavior on false AL is independent of any such written value. The stack output slot is not initialized by the reporter before each lookup and must never be used to infer a value on failure.

Shared set support establishes only the needed collection rule: `0x00624DD0` reads a full unsigned 32-bit value, uses unsigned remainder to select a bucket, compares full-word equality, and increments count only for a new value (`0x00624DD5`, `0x00624DEB`, `0x00624E00–0x00624E03`, `0x00624E32`). Equal values reuse the existing node and report an unused false insertion flag (`0x00624E4B–0x00624E57`). Thus zero and `0xFFFFFFFF` are admitted when conversion succeeds; duplicate values collapse. Helper `0x004F0940`, despite the exported name `begin`, conditionally grows/rehashes storage: `0x004F0955–0x004F095B`, `0x004F09D0–0x004F09E3`, `0x004F0A09–0x004F0A0F`. It is not a reporter traversal/filter decision. No reporter-side installed-pack lookup, value-range filter, numeric sort, persistent pack selection, retry or once-only latch appears. Ordering exposed by the foreign dialog or manager is not specified here.

### Cleanup and reference lifetime

The set is alive through `DoDialog`; the borrowed `&S` is not a persistent reporter field. List storage is alive during traversal and dialog, even though all occupant references have already been released before the dialog. On ordinary completion, shared cleanup `0x00413E60(&L)` visits forward links, reads each next link **before** freeing its node via `A[+0x10]`, and finally resets the sentinel's next and previous links to itself (`0x00413E64–0x00413E7A`, `0x00413EBA–0x00413ECC`). It does **not** release the node's occupant again.

For each node free that helper rereads global `A`; if null, it repeats the framework/out-pointer/cache/temporary-release sequence above (`0x00413E70–0x00413EB4`). After node cleanup the reporter independently reloads `A`, captures the sentinel, repeats that same lookup sequence if needed, and frees the sentinel via `A[+0x10](sentinel)` (`0x0048C868–0x0048C8B5`). These are real repeated acquisition sites, not an assumed permanently held allocator reference. No service lookup success-bit test or allocator-null fallback exists at any site. A nonnull lookup output is cached and then its temporary reference is released; continued cache liveness is an external requirement, not proof of an additional reporter-owned reference.

Finally `0x008EBA60(&S)` frees all set nodes and clears their buckets/count (`0x008EBA74–0x008EBAA9`); if the set's bucket-array pointer at `S+4` is nonnull the reporter calls shared deallocation primitive `0x0090CF63` (`0x0048C8B8–0x0048C8CF`). That primitive forwards its pointer to allocator support (`0x0090CF63–0x0090CF71`); the export's `cRZString::~cRZString` name is not evidence of a temporary string. The null-manager path does just this set cleanup, followed by AL zero. There is no list sentinel on that path. These are explicit normal-path calls, with no inferred RAII, exception unwinding, dialog self-ownership or foreign teardown behavior.

Neither body posts/sends a notification directly or registers/unregisters a listener. The received notification is publicly named **`kSC4MessagePostCityInitComplete`** (`re/class_id_table.tsv`, ID entry at `0x00B082B8`). Registration, notification production and any notifications inside foreign calls are outside this contract. Repeated matching notifications invoke fresh collection/gating each time; any suppression inside the foreign permission query, manager/filter or dialog is outside the reporter's own rules.

Query-AL-false with a partial nonempty list, and service-lookup-AL-false with a nonnull output, are deliberately caller-level conditional witnesses. This spec does not assert that those foreign providers produce those combinations. For a returning manager, the reporter's only tested collection output is the list, and for a returning service lookup its only subsequent input is the output pointer. Allocation-null, nonreturning foreign calls, stale pointer access, exception/reentrancy and count overflow have no invented terminal verdict.

## Limits and follow-up

This first round specifies the two reporter bodies and their necessary intrinsic adapters. It does not complete the owner or change the scope/caps of application, UI windows, dialogs, networking or missing-region-asset rules. The public dialog inventory remains an identity inventory; its caller now has this separate contract. The dependency `core-local-grid-helper4` is operational merged-claim provenance only. No implementation source, SDK implementation, native/game/runtime comparison, REA session, ABI change, build or test was used. Remaining native error-channel and lifetime questions are [MPR1–MPR3](questions/missing-plugin-reporter.md); they bound the contract instead of supplying guessed behavior.
